    FROM DIAGRAM TO YOUR OWN CODE
    Build the same workflow in Python.
    A small program you can read end to end. It uses actual LangGraph, a replaceable writer function, and a SQLite checkpointer. The default writer is deterministic; no API key is needed.
    Download Python starter
    
    
    01
    Start a reproducible run
    Unzip the starter. Open a terminal in that folder. Use Python 3.12, the version used for verification.
    python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell instead:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python workflow.py --config config.json --thread first-run
    The program prints the actual input, patch, and output for each completed node, then pauses for review.
    
    
    02
    Resume after restarting
    Close the Python process. From the same directory, use the same database and thread ID:
    python workflow.py --thread first-run --decision approve
# Or use --decision reject
    SQLite preserves the checkpoint in workshop.sqlite. Browser checkpoints last only until this page reloads; the Python version demonstrates durable resume.
    Use a new thread ID for each new experiment. A thread ID is a lookup key, not authentication.
    
    
    03
    Change one part at a time
    1. Download your configuration from Experiment and replace config.json.
    2. Add a note to sources.json. Keep IDs unique.
    3. Change retrieve() to search your own small dataset.
    4. Keep validate_draft() independent of the writer.
    5. Run the included evaluations before changing the model adapter.
    python -m unittest discover -s tests -v
    Try a retrieval limit of 1 with a minimum of 4 citations. A writer cannot repair evidence it never received. The next improvement is a route back to retrieval.
    
    
    04
    Add intelligence at one boundary
    build_graph(..., writer=your_writer) is the model boundary. Your function receives the selected evidence and validation feedback, then returns a list of {text, source_id} objects.
    Assemble instructions separately from untrusted source text. Require structured output, validate it, cap input and output, add a timeout, and count every attempted model call. The model does not get to approve itself.
    Live Osiris subscription inference is not enabled in this lab. It needs the approved hosted connection, this feature’s own server-side contract, consent and usage controls. Signing in alone is not permission to generate.

    THE PARTS, AND WHY THEY MATTER
    A workflow is more than a prompt.
    The graph decides what runs next. The model supplies judgment where you deliberately allow it. Your application owns state, permissions, evidence, and stopping.
    
    
    
      
    01 / Contracts and context
    Define the input, shared state, and expected output before writing prompts. A Python TypedDict documents shape; it does not validate model output at runtime. Validators do that work.
    Store evidence and decisions as structured fields. Pass each node only what it needs. A checkpoint is execution memory, not a user profile or a vector database.
    
      
    02 / Nodes, tools, and agents
    A node is a function. A tool does a bounded job such as retrieval or a calculation. An agent uses a model to decide actions in a loop. Giving five functions job titles does not create five intelligent coworkers.
    This lab is a controlled workflow with a practice writer. Start here; add autonomous tool selection only where it earns its complexity.
    
      
    03 / Routing and recovery
    Conditional edges turn evidence into control flow. No evidence stops the run. Invalid output gets a limited repair attempt. Valid output reaches a person.
    A repair changes the content using feedback. A transport retry repeats a failed request, usually with backoff. This lab teaches repair; it makes no network requests to a provider.
    
      
    04 / Checkpoints and review
    The browser pauses at LangGraph node boundaries and resumes with updateState(). The Python version uses interrupt() and Command(resume=...) with durable SQLite storage.
    An interrupted Python node restarts on resume. Keep external effects after approval and use an idempotency key so a retry cannot publish or charge twice.
    
      
    05 / Traces and evaluations
    Observe inputs, outputs, tool results, routing, errors, latency, and usage. Those are execution records, not a model’s hidden reasoning.
    Keep test cases for good evidence, unknown citations, empty retrieval, failed repair, approval, rejection, and recovery after a restart. A second model’s opinion is another signal, not ground truth.
    
      
    06 / From lesson to service
    Keep the interface on the site. Run live graphs behind an authenticated service with per-user checkpoint ownership, bounded concurrency, timeouts, cancellation, and usage limits. Never execute a visitor’s arbitrary Python on the public server.
    Start with this fixed graph and editable configuration. Python needs a Python-capable host; a JavaScript graph needs a compatible runtime. LangGraph does not require DigitalOcean or its own managed hosting.
